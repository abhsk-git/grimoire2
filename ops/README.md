# Grimoire archives and migration

Uploaded avatars, banners, post covers, and inline uploaded images are stored as bytes in the `media_assets` MariaDB table. A normal SQL dump therefore carries the media with the application data; no upload directory needs to be copied separately.

## Database migration

Create a dump on the source host:

```sh
docker exec grimoire-db sh -lc 'mariadb-dump -u"$MYSQL_USER" -p"$MYSQL_PASSWORD" "$MYSQL_DATABASE" --single-transaction --routines --events' | gzip > database.sql.gz
```

Restore it into the destination MariaDB container after creating the database/user:

```sh
gunzip -c database.sql.gz | docker exec -i grimoire-db sh -lc 'mariadb -u"$MYSQL_USER" -p"$MYSQL_PASSWORD" "$MYSQL_DATABASE"'
```

Keep the matching `api/config/.env` and application source/configuration with the dump. The media endpoint is `/api/media/<asset-id>`.

## Local rolling archives

`ops/rotate-grimoire-archives.sh` writes one UTC folder per day under `/opt/grimoire2/runtime/archives`, containing a compressed database dump and the last 24 hours of Docker logs. `/etc/cron.d/grimoire-archive` runs it daily at 02:17 UTC and removes folders older than three days. The directory is intentionally git-ignored.

Docker's live JSON logs are normally under `/var/lib/docker/containers/<container-id>/<container-id>-json.log`; use `docker logs grimoire-backend` for the supported view. Security events generated by the API are also retained in the database `security_log` table.
